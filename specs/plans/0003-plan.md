**Kontrolün tasarımı:** shebang'li dosyalar tek `git grep --cached -I -n -e '^#!'` çağrısıyla, git'teki
içerikten (index) bulunur ve yalnızca `1:` satırında eşleşenler alınır; her birinin modu `git ls-files -s`'ten
okunur. Dosya sistemi izni hiç okunmaz (CB-2). `120000` (symlink) ve `160000` (submodule) atlanır. Git deposu
değilse not yazıp 0 ile çıkar (CB-5). İhlalde her yol + `git update-index --chmod=+x <yol>` yazılır, çıkış 1.

**Test senaryoları** (`tools/exec-bits.test.sh`; geçici git deposu `mktemp -d` ile repo **dışında**,

`git update-index --chmod` / `git add --chmod` ile verilir, `chmod` ile asla — CB-2):

## Risks & open questions
- **R1 — Windows'ta `sh` ve `mktemp`.** `scripts/check` zaten `sh` ile çalışıyor; Git Bash'te `mktemp` mevcut
  (doğrulandı). **Önerim:** başka araç kullanılmaz (`git`, `sed`, `cut`, `head` dışında).
- **R2 — Geçici deponun üst dizini bir git deposuysa** T6 yanlış sonuç verebilir. `mktemp -d` sistem temp
  dizinini kullanır; T6, `GIT_CEILING_DIRECTORIES` ile üst dizin aramasını kapatır. **Önerim:** bu korumayı eklemek.
- **R3 — Geçici depoda commit için kimlik.** T1 commit gerektirir; `git -c user.name=… -c user.email=…`
  yalnızca o komut için verilir, global ayar değişmez.
- **R4 — Süre.** Kontrol tek `git grep` + birkaç `ls-files`; test ~7 küçük git işlemi. İkisi de saniyeler
  mertebesinde, `[fast]` uygun. Ölçüm adım 4'te check'in kendi zamanlarından raporlanır.
- **R5 — Kalıntı/veri.** Arka plan süreci yok; geçici depo `trap ... EXIT` ile silinir, ayrıca test sonunda
  silindiği doğrulanır (rule 5). Repo içinde hiçbir şey yazılmaz.
- **R6 — Adım 2'deki kasıtlı kırmızı.** Gerçek depodaki ihlal CB-1'in en doğrudan gözlemi olduğu için önce
  kırmızı gösterilir, sonra düzeltilir; kırmızı hâl commit'lenmez.
